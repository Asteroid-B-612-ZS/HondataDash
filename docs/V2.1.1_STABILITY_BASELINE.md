# HondataDash V2.1.1 Stability Baseline

Status: **PRE-V3 FINAL STABILITY CANDIDATE**

This baseline is the last planned structural refinement before real-car soak validation.
If road validation passes, the intended next product step is promotion to **V3.0**
without further feature expansion. After that, development should be maintenance-only
unless new real-car evidence proves a defect.

## Approved product delta

Only the following five changes are approved for this candidate.

### 1. Fuel-pressure display truthfulness

BT42 PID `0x191` is already decoded in **bar**. The UI now displays that value
directly instead of dividing by 100.

The legacy target-tracking alert is deliberately disabled because `0x190` target
scaling has not yet been proven strongly enough for production use. A non-working or
unit-mismatched protection path is worse than an explicitly disabled one.

Deferred:
- absolute 20 bar critical-floor alarm
- target-following pressure alarm
- any new F.P threshold

Those require separately proven scaling/behaviour.

### 2. IGN recovery sentinel presentation hold

After combustion admission releases, real BT42 logs can still contain the fuel-cut
IGN sentinel (observed as 117.5 degrees) for a few frames.

A 500 ms presentation-only guard now keeps the last trusted IGN value in HOLD when
the incoming IGN is physically invalid.

Frozen:
- `CombustionDisplayAdmission`
- SHIFT/DFCO semantics
- IGN physical range
- confidence/state logic

The guard never delays a physically valid recovered IGN sample.

### 3. Closed-loop A/F colour attack

WOT protection remains unchanged:

- danger/red attack: 100 ms
- warning/amber attack: 150 ms

Ordinary closed-loop colour confirmation is deliberately calmer:

- danger/red attack: 1000 ms
- warning/amber attack: 1500 ms

Measured/target lambda values remain live. Only colour escalation is debounced.

### 4. K.Control text cadence

K.Control text now follows the existing 200 ms auxiliary display cadence.

Unchanged:
- K.Control data
- 55 / 65 legacy threshold logic
- per-frame alert/event evaluation
- presentation mapping

A future K.Control threshold redesign is explicitly deferred. Hondata K.Control has
real directional/diagnostic meaning; it must not be reduced to a guessed fixed-threshold
policy without stronger calibration evidence.

### 5. A/F target marker

The A/F target marker is structural information, not an alarm lamp. It now uses the
subdued `DashboardPalette.SCALE_TARGET` colour independent of main-digit severity.

The main A/F number remains the owner of warning/danger colour.

## Explicitly deferred

The following research items are **not** part of V2.1.1:

- IGN load-context colour gating (current AND/OR evidence is not frozen)
- IAT load-context/attack redesign
- K.Control colour/threshold redesign
- 20 bar fuel-pressure critical floor
- restored fuel-pressure target tracking before `0x190` scaling is proven
- MAX/MIN optical-weight experiments
- MAP text-rate experiment
- Critical-colour experiment
- broad palette/CYAN normalization for unused future paths

These may be revisited only with specific real-car evidence, not as aesthetic cleanup.

## Frozen product behaviour

Do not change without evidence of a real defect:

- Bluetooth connect/reconnect/polling ownership
- BT42 protocol/channel interpretation except proven PID bugs
- SHIFT recognition
- DFCO / OTHER_FUEL_CUT separation
- `CombustionDisplayAdmission`
- TP plausibility upper bound 105%
- TrustedDisplayMemory
- EphemeralDiagnosticMemory bounded RAM-only behaviour
- production no-recorder boundary
- Last Boost Event Peak
- main 4x2 geometry
- shift-light geometry and thresholds
- normal cold-white digit principle
- semantic HOLD/SYNC/confidence presentation
- Fuel Pressure 8 s legacy tracker implementation (retained but not called by production until units are verified)

## Real-car acceptance before V3.0 promotion

Use ordinary commuting; no deliberate abuse is required.

Required observations:

1. Cold start and ordinary warm-up remain normal.
2. Warm reconnect does not show placeholder data as live.
3. Pause/resume (HVAC/phone UI) returns cleanly to LIVE.
4. SHIFT/DFCO/HOLD behaviour remains coherent.
5. IGN no longer briefly blanks/dims after ordinary fuel-cut recovery.
6. Closed-loop A/F remains mostly quiet; WOT warning response remains immediate.
7. F.P displays physically credible bar values (roughly tens of bar at idle/light load,
   rising appropriately with demand); no production F.P alarm is claimed in this build.
8. K.Control text is visually calmer while existing event/colour logic still works.
9. A/F target marker remains subdued and does not turn green merely because the reading is safe.
10. No persistent logs/storage growth.
11. No unexplained STALE/DATA LOST or long-run lifecycle degradation.

## Promotion rule

If the candidate passes normal real-car soak testing, promote the proven product state
to **V3.0**. Do not add new product behaviour during promotion.

After V3.0, default policy is bug-fix maintenance only.
