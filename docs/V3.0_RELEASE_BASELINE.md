## Product philosophy

Normal driving should remain visually quiet. Values should be truthful, warning colours
scarce and credible, and proven state-machine/transport behaviour should not be changed
without reproducible evidence.

## Frozen product behaviour

The following are frozen unless a confirmed defect requires a minimal change:

- Bluetooth connection/reconnection/polling ownership
- BT42 protocol interpretation
- SHIFT / DFCO / OTHER_FUEL_CUT semantics
- CombustionDisplayAdmission
- TP plausibility upper bound 105%
- TrustedDisplayMemory
- EphemeralDiagnosticMemory bounded RAM-only behaviour
- production no-recorder boundary
- Last Boost Event Peak
- main 4x2 geometry
- shift-light geometry and thresholds
- normal cold-white presentation
- HOLD / SYNC / confidence semantics
- V2.1.1 five approved truthfulness/calmness changes

## Maintenance policy

V3.x is maintenance-first.

Allowed reasons to change product code:
1. reproducible bug
2. verified PID/unit error
3. Android/device compatibility defect
4. truthfulness/safety issue supported by evidence

Not sufficient by itself:
- aesthetic preference
- speculative threshold tuning
- refactor-only cleanup
- feature expansion without a demonstrated user problem

Maintenance workflow:
Evidence -> Reproduce -> Minimal Fix -> Regression -> Real-car validation -> Patch release.
