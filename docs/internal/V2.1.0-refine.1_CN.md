# V2.1 OEM Refinement 1

日期：2026-09-23。版本 `2.1.0-refine.1 / 56`。

在 `feature/v2.1-oem-refinement` 独立分支推进。实现基线为已经交付的 visual.3：`db607ab745767f019465ae173aca05f6639af9fc`；正式产品来源为 `master@6cedcdd14fe0d6c1357129fa3e65388acffc3ebc`。本候选需要自己的构建结果与实屏验收，不能继承旧版 CI 或实车通过的结论。

## 设计结论

延续近黑底、冷白读数、冷银细边、低亮度区间条及局部警示色。继续采用 4×2 卡片、5+5 转速灯、E99 常规字号与真实 E100 的完整适配。

优化集中于减少无效呈现工作与完善交付门禁。数字与白色指针继续直接对应同一个已准入的显示值；不新增数字滚动、数字交叉淡化或指针弹跳。

实际 `configureScaleBar()` 对八张卡片全部调用 `setStatic()`。ScaleBarView 中的旧热量、弹簧和包络代码不等于正在运行的效果。不能依据旧注释重新启用这些效果。

## 数据变化速度

以下是刷新下限间隔，不是车机实测帧率。数据未变化时允许不重绘，但每个到达的帧仍经过原有语义处理。

| 信息 | 现有显示间隔 | 本轮处理 |
|---|---:|---|
| Ethanol / ECT / IAT | 500 ms | 保持；缓慢量适合稳定阅读 |
| L.TRIM | 1000 ms | 保持；长期学习量不需高频跳字 |
| MAP | 50 ms | 保持；不增加展示插值延迟 |
| A/F、IGN | 100 ms；原有高负荷条件下 50 ms | 保持原有自适应条件 |
| S.TRIM | 200 ms | 保持 |
| 底部普通辅助数值 | 200 ms | 保持；告警与爆震事件依照原有路径处理 |
| RPM 灯 | 随有效 RPM 样本，按原有阶段/迟滞绘制 | 保持 |
| 链路新鲜度检查 | 250 ms | 保持；500/1500 ms 状态边界不变 |

蓝牙 `POLL_INTERVAL_MS=20` 是每次通信后的等待；连同请求、接收、解析和调度耗时，不能直接宣称稳定 50 Hz 或某个端到端延迟。

Ethanol/IAT 的 EMA 为 0.05，ECT 为 0.1，IGN 为 0.4，S.TRIM 为 0.2；A/F 和 MAP 另有工况适配。EMA 按有效输入帧推进，真实时间响应依赖接收节奏。本次保留这一已验证行为。改变滤波常数或换成时间常数模型，会同时影响告警输入、可信值与部分极值，需要另立语义回归任务。

## 过渡与 OEM 体感

| 情境 | 保留或新增的处理 |
|---|---|
| 普通数据变化 | 定宽数字格、固定参考宽度；立即替换已准入文字，不显示两个数值叠影 |
| 数字位数改变 | 继续采用原有字体适配；E9→E10、负号、E99→E100 的规则不变 |
| HOLD / SYNC / 恢复 | 完整保留现有准入、文字、alpha、释放与滤波重置；不追加淡入等待 |
| 警示进入与解除 | 原有 attack、400 ms 恢复锁定、闪烁相位不变 |
| 冷启动 | 默认 2900 ms；最后 600 ms 的原有缓出淡入、点击跳过与回前台不重播均保留 |
| 系统动画倍率为 0 | 新增：直接展示仪表。只读取系统设置，不修改设置、不增加应用选项 |
| 非零系统动画倍率 | 保留原有固定 2900 ms；本轮只尊重“关闭”状态，不宣称跟随所有倍率 |

## 已实施内容

1. `MainActivity.applyOemPalette()`：只有最终颜色发生变化时才写 TextView；无效 CYL 灰显、事件黄与快速累计红仍执行原条件。
2. `setConnectionStatus()`：相同文本/颜色不重复写入，避免稳定 LIVE 每 250 ms 重设文本。状态判断和出现时间不变。
3. `ScaleBarView.setValue()`：静态模式的相同有效值不重复使视图失效；重复无效值不重复绘制空轨道。有效→无效、新数值、TARGET 更新、监控状态和布局变化仍可立即重绘。旧动态接口继续保留。
4. `FittedTextView.setFitReference()`：相同配置保留已复制的参考数组及字形缓存；引用内容、字体或语义配置变化仍触发原有测量。
5. `StartupOverlayView`：复用 FontMetrics，跳过全透明背景和占位文字；系统关闭动画时直接完成启动幕布。
6. `StartupBrandRenderer`：品牌已经完全淡出后停止绘制不可见内容。

未引入新的运行库、线程、持续动画循环或遥测记录。应用继续使用 Android Framework，minSdk 17、targetSdk 28、compileSdk 33；字体保持固定版本的 Roboto Condensed。这里的 API 17 静态检查不等于真实 API 17 设备验收。

## 修复的交付门禁问题

原 `verify_oem.py` 在缺少正式基线历史时会 SKIP；原视觉 CI 默认浅克隆，因此其 SUCCESS 不能证明完成了 Git 基线比较。完整仓库实际执行时，又有四个已不存在的方法签名导致检查退出。

本轮修复为：

- 新构建流程 `fetch-depth: 0`，调用 `verify_oem.py --require-baseline`；缺少历史必须失败。
- 将四个不存在的方法名替换为当前实际执行的方法，保留 23 项明确方法对比。
- 新增 visual.3 整体冻结检查：MainActivity 除两处指定呈现方法外逐字相同；`data/`、资源、Manifest、颜色、RPM、文字几何、ColorRecovery 和 StartupSequence 必须不变。
- 固定三份字体 SHA-256；下载后以及最终 APK 中分别校验。
- 在 R8 后检查最终 APK 的所有 DEX、Manifest 与资源，阻止 Recorder、文件遥测写入、存储权限和意外 native 库回流。

## 安装和正式交付的限制

现有 Gradle 使用 `signingConfigs.debug`。visual.3 APK 的签名证书 SHA-256 为 `e4de2e802654927a770835bbde81fd455fc45fa5635fbd866796ebb57e5694fb`。旧签名私钥没有包含在源码或该 APK 交付包中。APK 的证书不能用于恢复私钥。

本轮沿用现有候选构建方式，不擅自更换正式签名体系。新候选需要比较签名；同 applicationId 若证书不同，Android 不能直接覆盖安装。不要把卸载已验证版本作为默认升级步骤，卸载会移除该应用的本地设置。

因此本分支是可审查的精修候选，保留原版、master 和现有视觉分支。正式 Stable 升级包必须采用可长期保管的签名身份，并完成目标车机短验收：默认/关闭动画、稳定读数、HOLD恢复、断连灰显及前后台切换。若仍持有已安装版对应的签名私钥，应复用该私钥构建。
