# HondataDash V2.0.1-internal.2 / V2.0.T2

## 1. 定位

本版本是 V2.0.1-internal.1 之后的开发基础设施版本。

唯一新增能力：

**HondataDash Flight Recorder（车载黑匣子）**

Change Classification：

**Development Infrastructure / Diagnostic Flight Recorder**

本版本不是新的显示语义版本，不以改变 SHIFT、DFCO、Recovery、ThermalContext、Fuel Pressure、Extrema、Bluetooth polling 或 UI 行为为目标。

生产语义基线：

`d0703f068517ae43e9a18492a65d4e4f4655f837`

IT1 最终 HEAD：

`de24885c8cdd90a83f3b30b28d759d02637d72bc`

IT2 分支：

`internal/v2.0.1-it2`

版本身份：

- versionName: `2.0.1-internal.2`
- versionCode: `46`
- applicationId: `io.github.asteroidb612zs.hondatadash.internal`
- launcher: `Hondata Dash IT2`

## 2. 核心不变量

IT2 必须满足：

1. Diagnostic Recorder 只观察，不参与 ECU/显示决策。
2. 不增加任何 FlashPro Bluetooth 命令。
3. `CMD_SENSOR_DATA` 的请求频率、顺序、超时、重连逻辑保持 IT1。
4. 不修改 `HondataProtocol` 缩放/解析语义。
5. 不修改 EngineStateTracker / CombustionDisplayAdmission 的状态判定。
6. 不修改 A/F、IGN、S.TRIM recovery 常数。
7. 不修改 Fuel Pressure 8 s evidence TTL 和报警阈值。
8. 不修改主界面、转速灯、颜色和 extrema admission 规则。
9. Recorder 队列满或存储失败时允许丢诊断证据，但不得阻塞 Bluetooth/UI 主链。
10. 关闭 Recorder 或存储不可用时，HondataDash 必须继续正常工作。

目标：

**Semantic behavior delta = ZERO**

## 3. 数据来源

Flight Recorder 不主动请求额外 PID。

FlashPro 现有握手仍然：

`CMD_INIT → CMD_SENSOR_DEF → CMD_SENSOR_DATA`

Recorder 保存当前 session 实际返回的动态 Channel Manifest；不假定固定 21 或固定 42 个 PID。

对未充分验证的额外 Channel：

- 保存 CID / CS / CT / size；
- 保存原始 0x35 frame；
- decoded 数值仅作为协议层结果；
- 不自动加入 Engine Semantic State 或报警逻辑。

## 4. 存储位置

默认公共存储：

`/storage/emulated/0/HondataDash/Diagnostics/`

不同车机文件管理器可能显示为：

`内部存储/HondataDash/Diagnostics/`

用户需要分析时，用车机文件管理器复制对应 session 文件夹到 U 盘即可。

IT2 不实现额外 U 盘导出流程。

## 5. Session 目录

每个 session：

`YYYYMMDD_HHMMSS_IT2/`

包含：

- `session.json`
- `channel_manifest.csv`
- `raw_frames.bin`
- `semantic_trace.csv`
- `events.csv`
- `extrema.csv`
- `recorder_stats.json`
- `COMPLETE` 或 `INCOMPLETE`

### session.json

记录：

- App/versionCode
- semantic baseline
- recorder version
- wall-clock start
- monotonic start
- ChannelCount
- data frame length
- manifest identity
- trace interval
- raw binary format说明

### channel_manifest.csv

记录当前 FlashPro session 实际公布的：

- index
- CID
- name（当前 HondataProtocol 映射）
- CS
- CT
- byte size

该文件用于解决不同 ECU / FlashPro session 的 Channel 集合差异。

### raw_frames.bin

完整保存现有 Bluetooth polling 已经收到的有效 0x35 frame。

Recorder 不为此增加任何 Bluetooth 请求。

raw frame 与 decoded/semantic trace 通过：

- frameSequence
- elapsedRealtime

关联。

保留 raw frame 的目的：

即使未来发现某个非核心 Channel 的 CT/缩放解释需要修订，也可以重新解析历史驾驶数据。

### semantic_trace.csv

目标 20 Hz（50 ms）。

记录：

- 当前 Manifest 中全部 decoded Channel
- MainState
- ThermalContext
- SubState
- Modifier
- ShiftPhase
- CombustionState
- confidence
- A/F / IGN / S.TRIM admission
- release/front-guard
- A/F / IGN / S.TRIM 当前有效显示语义值
- S.TRIM presentation weight
- Fuel Pressure observable/evidence/alert 状态

### events.csv

事件驱动记录：

- Bluetooth connected/lost
- MainState transition
- Thermal transition
- SubState transition
- Modifier transition
- ShiftPhase transition
- CombustionState transition
- A/F / IGN / S.TRIM HOLD ↔ LIVE
- TIP_OUT front guard
- Fuel Pressure alert transition

### extrema.csv

当前版本记录已实际写入 extrema memory 的初始化/更新事件。

注意：

它记录 **admitted extrema changes**，不是所有 rejected candidate。

Rejected candidate 可结合 `semantic_trace.csv`、状态和当前 extrema admission 规则离线重放。

### recorder_stats.json

用于判断本次诊断数据是否完整：

- rawReceived
- rawWritten
- rawDropped
- traceWritten / traceDropped
- eventWritten / eventDropped
- extremaWritten / extremaDropped
- writeErrors
- 各队列最大深度

道路测试优先要求：

`rawDropped = 0`

并检查所有 writeErrors/dropped counters。

## 6. 性能隔离

Bluetooth polling / UI hot path：

- 不执行 File I/O；
- 不执行 ZIP；
- 不实时 SHA 整个 session；
- 不等待 writer；
- bounded queue 满时丢 Recorder data。

Writer：

独立 daemon thread：

`Hondata-FlightRecorder`

采用 buffered sequential write。

主要队列：

- raw frame: 1024
- semantic trace: 256
- event: 256
- extrema: 256

## 7. Session 生命周期

第一份可记录证据到达并确认协议 Manifest 后创建 session。

短暂 Bluetooth 断开：

- 记录 transport event；
- 不立即强制结束 session。

连续约 60 s 无新有效 frame：

- 完成并关闭 session。

异常中止：

下次 Recorder 初始化时，未存在 COMPLETE/INCOMPLETE marker 的旧目录标记为：

`INCOMPLETE`

## 8. 空间管理

保护阈值：

- Diagnostic 总量目标上限约 1 GB；
- COMPLETE session 最多约 30 个；
- 仅自动清理最老 COMPLETE session；
- 不自动删除 INCOMPLETE session；
- 可用空间低于约 200 MB 时 Recorder 停止写入，HondataDash 主功能继续运行。

## 9. 首次实车验证目标

第一次 IT2 通勤数据首先确认：

1. 实际 ChannelCount；
2. 实际 frame length；
3. channel_manifest；
4. raw/semantic frame 对齐；
5. rawDropped / traceDropped；
6. Bluetooth 稳定性是否等同 IT1；
7. UI/SHIFT/DFCO/recovery 是否无可感知差异；
8. 热机、换挡、DFCO、DFCO→throttle、neutral coast、Fuel Pressure pause 的 event timeline。

## 10. Release Gate

IT2 只有在以下条件满足后才算 Road-Test Ready：

- 现有静态 QA 全部通过；
- IT2 Flight Recorder observer-boundary QA 通过；
- Android release build 通过；
- package/version/signing identity 验证；
- Core14 与 IT1 对比无非预期 semantic delta。

如果 Recorder 导致任何 Bluetooth timing、状态机、显示 admission 或 Fuel Pressure 行为差异：

**IT2 FAIL，不上车。**
